# 段階0：ホールの実データ（当たり履歴など）を自動で集めてよいか

確認日：2026-10-28。確認した場所：クラウドの作業環境（robots.txt は通常のアクセスで取得。利用規約はサイトの規約ページを通常のアクセスまたは Web 取得で読んだ）。
**ブロックや取得対策（Cookie の発行・ボット判定）を回避するアクセスはしていない。** 読めなかったものは「不明」にした。

## 判定の決まり

- **よい**：利用規約に自動収集の禁止がなく、robots.txt でも対象ページが許可されていて、取得対策もない。かつ、集めたデータをもとにした独自の計算結果を有料記事で使うこと（商用利用）が禁止されていない
- **だめ**：利用規約で自動取得・二次利用・商用利用のどれかが禁止されている、robots.txt で対象ページや AI による取得が禁止されている、または取得対策（Cookie 必須・ボット判定）がある
- **不明**：規約が読めない・書いていない。**不明のサイトからは集めない**
- 有料データサービス（会員だけが見られるデータ）は、規約に関係なく**中身を使わない**

## 結論

- **「よい」のサイトは 0 件。** どのサイトからも自動では集めない
- 運営者の実戦記録も使わない（母数が少ないため。2026-10-28 決定）
- そのため **段階3（実データで補正）は今回は行わない**。生存時間分析のコード（`pipeline/ev/survival.py`）は作り、合成データでのテストだけ通しておく。将来「よい」のサイトが見つかるか、許可を得たときに使う
- 記事の期待値は「シミュレーション（設定1）＋公開されている期待値表との答え合わせ」だけで作り、「実際のホールでは」という参考値は出さない

## 見直すとき

- 規約は変わるので、使う前にもう一度確認する。許可をもらう場合は、サイトの問い合わせ窓口に「個人が有料記事の独自試算に使う」「取得の間隔」「出典の書き方」を伝えて、文書で許可を得る
- このファイルに「よい」を足すときは、規約の該当条文と確認日を必ず書く
